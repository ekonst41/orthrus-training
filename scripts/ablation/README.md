# Абляция: взвешенный лосс по позициям блока

## Что проверяем

Orthrus за один проход черновика предлагает блок из 31 токена. AR-модель принимает их по порядку
до первой ошибки, а всё после первой ошибки выбрасывается. Поэтому первые позиции блока важнее
последних: ошибка в 1-м токене обнуляет весь блок, ошибка в 25-м почти ни на что не влияет.

В статье все позиции учатся с одинаковым весом. В этой абляции позиция `i` (0 — первый токен
после якоря) получает вес `exp(-i/γ)`, а лосс — взвешенное среднее KL. Так делает DFlash
(arXiv 2602.06036); Medusa и EAGLE-3 используют похожие веса `0.8^k`.

Всё остальное — модель, данные, порядок батчей, якоря, LR — совпадает с готовым базовым прогоном
`qwen3-0.6b-paper` (равные веса). Сравнение с ним показывает эффект только весов.

| Скрипт | γ | Вес 8-го токена | Вес 16-го | Доля веса на первых 8 позициях |
|---|---|---|---|---|
| (база, уже обучена) | — | 1 | 1 | 26% |
| `gamma4.sh` | 4 | 0.17 | 0.02 | 87% |
| `gamma8.sh` | 8 | 0.42 | 0.15 | 65% |
| `gamma16.sh` | 16 | 0.65 | 0.39 | 46% |

Главная метрика — **TPF** (токенов на прямой проход модели; больше — быстрее генерация). Ускорение
должно появиться как рост TPF при `ar_match = 1` (вывод не меняется).

## Что нужно

- Linux-сервер с GPU NVIDIA и драйвером **535 или новее**. Обучению нужно ~39 ГБ памяти GPU:
  подходят A100/H100 80GB (базовый прогон обучен на A100 80GB), хватит и 48 ГБ.
  Одна GPU на прогон: три прогона параллельно — три GPU.
- **~40 ГБ** на диске, интернет (PyPI, PyTorch, Hugging Face).
- `git`, `curl` и компилятор C (`gcc`). На Ubuntu: `sudo apt install git curl build-essential`.
- Токен Hugging Face с доступом к бакету `Danchik575/orthrus-training` (там данные и базовый прогон;
  туда же пишутся чекпойнты). Токен выдаёт владелец бакета.

sudo для самих скриптов не нужен; Python и библиотеки ставятся в папку проекта.

## Пошагово

Все команды — из корня репозитория (папка `orthrus-training`).

### 1. Скачать код

```bash
git clone -b exp/position-weighted-loss https://github.com/ekonst41/orthrus-training.git
cd orthrus-training
```

### 2. Поставить окружение (~5 минут)

```bash
bash scripts/ablation/setup.sh
```

В конце должна быть строка вида `torch 2.13.0+cu129, CUDA 12.9, 4 GPU, GPU 0: NVIDIA A100-SXM4-80GB`
и `окружение готово`.

### 3. Вписать токен и бакет

Создайте в корне репозитория файл `.env` (он не попадает в git):

```bash
cat > .env <<'EOF'
HF_TOKEN=hf_ваш_токен
ORTHRUS_BUCKET=Danchik575/orthrus-training
EOF
```

### 4. Скачать модель и данные (~5-10 минут)

```bash
bash scripts/ablation/prepare.sh
```

Ожидаемый итог: `251254 строк по 2048 токенов ..., 192 отложенных промптов`.

### 5. Самопроверка (~10 минут)

```bash
bash scripts/ablation/selftest.sh
```

Скрипт делает 3 шага обучения, экспорт и оценку и проверяет результат. Если в конце
**`САМОПРОВЕРКА ПРОЙДЕНА`** — машина готова к долгим прогонам. Если нет — причина в сообщениях
выше (см. «Если что-то пошло не так»).

### 6. Запустить прогоны (~29 часов на A100)

**а) Три GPU или больше** — всё одной командой:

```bash
bash scripts/ablation/start_all.sh          # gamma 4, 8, 16 на GPU 0, 1, 2
bash scripts/ablation/start_all.sh 3 5 6    # или на любых других свободных GPU
```

**б) Меньше трёх GPU** — по одному прогону на GPU, в фоне:

```bash
mkdir -p logs
nohup bash scripts/ablation/gamma8.sh 0 > logs/gamma8.log 2>&1 &   # начните с gamma=8
```

Когда он закончится, так же запустите `gamma4.sh` и `gamma16.sh`.

Прогоны работают в фоне: терминал и ssh можно закрыть. По окончании обучения каждый скрипт сам
делает итоговую оценку (fp32, 512 токенов, ~45 минут).

### 7. Следить за ходом

```bash
bash scripts/ablation/status.sh     # состояние, шаг, ETA и таблицы сравнения с базой
tail -f logs/gamma8.log             # живой лог одного прогона (выход: Ctrl+C, прогон не прервётся)
nvidia-smi                          # загрузка GPU
```

Каждые 10 шагов (~5 минут) в лог пишется строка `step N/3920 loss ... eta X.Xh`, где `eta` —
часов до конца обучения. Оценки на отложенных данных — каждые 500 шагов (~3.7 ч), они сразу
видны в `status.sh`.

### 8. Результат

`status.sh` печатает три таблицы:

1. **Последняя оценка во время обучения**: согласие с AR-моделью на позициях 1/4/8/16
   (`agree_k*`), ожидаемая длина принятия (`accept_proxy`), KL без весов (`kl`), TPF. Ожидаем рост
   `agree_k1..k8` и `accept_proxy` относительно базы; `kl` и `agree_k16` могут ухудшиться — это
   цена, которую мы платим за хвост блока.
2. **TPF по шагам** — все прогоны рядом, на тех же шагах, что и база.
3. **Итоговая оценка** — TPF на отложенных промптах, GSM8K, MATH-500, HumanEval, MBPP; среднее
   и изменение относительно базы в процентах. `ar_match` обязан быть 1.

Результаты также лежат в бакете: `runs/qwen3-0.6b-gamma*/` (`eval-final-512-float32.json`,
`train_metrics.jsonl`, модель в `final/`).

## Остановить и продолжить

```bash
bash scripts/ablation/stop.sh 8      # один прогон (gamma=8)
bash scripts/ablation/stop.sh all    # все
```

Обучение доделает текущий шаг, сохранит чекпойнт и выйдет (1-3 минуты). Продолжить —
той же командой, которой запускали (`start_all.sh` или `gamma8.sh`): обучение пойдёт с последнего
чекпойнта, результат будет таким же, как без остановки. Чекпойнты сохраняются каждые 100 шагов
(~45 минут), поэтому после сбоя или перезагрузки теряется не больше 45 минут.

## Если что-то пошло не так

| Сообщение | Что делать |
|---|---|
| `нет nvidia-smi` / `torch не видит GPU` | Нет драйвера NVIDIA или он старее 535: обновите драйвер. |
| `нет компилятора C` | `sudo apt install build-essential` |
| `не задан HF_TOKEN` / `ORTHRUS_BUCKET` | Шаг 3: файл `.env` в корне репозитория. |
| `401` / `403` / `в бакете нет data/...` | У токена нет доступа к бакету: попросите владельца. |
| `нет окружения .venv` | Шаг 2: `bash scripts/ablation/setup.sh` |
| `данные не подготовлены` | Шаг 4: `bash scripts/ablation/prepare.sh` |
| `CUDA out of memory` | GPU занята чем-то ещё (`nvidia-smi`) или памяти меньше ~40 ГБ: добавьте в конец команды `train.micro_batch_size=2`. |
| `cannot resume ...: settings changed` | Прогон с этим именем уже начат с другими настройками. Не меняйте настройки у начатого прогона. |
| `GPU N нет` | Укажите номера, которые показывает `nvidia-smi`. |
| Прогон пропал из `status.sh` | Смотрите конец лога: `tail -50 logs/gamma8.log`. Обычно достаточно запустить заново. |

## Для тех, кто хочет менять настройки

Любой скрипт `gamma*.sh` принимает после номера GPU дополнительные настройки `раздел.ключ=значение`
(все ключи — в `orthrus/config.py`). Например, другой γ без нового скрипта:

```bash
RUN=qwen3-0.6b-gamma6 nohup bash scripts/ablation/gamma8.sh 0 train.loss_gamma=6 > logs/gamma6.log 2>&1 &
```

Короткая абляция вместо полной (база тогда тоже нужна своя, с тем же числом шагов, т.к. расписание
LR сжимается):

```bash
RUN=qwen3-0.6b-gamma8-1k bash scripts/ablation/gamma8.sh 0 train.max_steps=1000
RUN=qwen3-0.6b-gamma0-1k bash scripts/ablation/gamma8.sh 1 train.max_steps=1000 train.loss_gamma=0
```

Сравнить любые прогоны: `python -m orthrus.compare --config configs/qwen3-0.6b.yaml --runs A,B,C`.
Реализация лосса — `orthrus/objective.py` (`position_weights`, `orthrus_loss`).
